# 단계별 Recall 스코어보드 (A → I)

테스트셋: `test.json` — **12케이스 / 정답 24개**. 에이전트를 통해 질문을 넣어(LLM이 실제로
툴 호출) 측정. 지표는 정답 단위(정답 24개 중 몇 개를 맞혔나), MRR은 최종 추천의 첫 정답 순위.

- **수집** = 정답이 collect_places 풀에 있나
- **리랭크** = 정답이 리랭크 top-15에 있나
- **최종(정답)** = 정답이 최종 추천에 있나 / **케이스최종** = 케이스당 하나라도 맞혔나

> ⚠️ 단일 실행이라 **최종·MRR은 최종 LLM 선정의 비결정성**에 흔들린다. 리랭커 비교는
> **리랭크 recall**이 더 안정적인 신호다. (리랭크는 A~E 중 일부는 후속 재계산값)

## 발전 흐름 — 어디서 뭐가 올랐나

**① 수집 recall: 83.3% → 95.8% (A→B)**
웹수확이 카카오가 놓친 로컬 노포(개성순대·우동한그릇 등)를 잡아 +12.5p. 이후 계속 유지.

**② 랭킹 도입: 케이스최종 50→75%, MRR .27→.53 (B→C)**
HyDE 스니펫 임베딩 리랭크로 풀을 top-15로 좁히니 최종 품질이 크게 개선.

**③ 임베딩 천장 62.5% 발견 (C·E·F)**
스니펫이든 본문이든(D), HyDE를 담백화해도(E) **리랭크 top-15가 62.5%에 막힘.** 같은
도메인(맛집 후기)에서 코사인 유사도가 평평해 미세 변별을 못 하는 게 원인.

**④ 천장 돌파: 리랭크 62.5% → 75% (G)**
LLM-judge(스니펫 읽고 추론)로 임베딩의 flat 한계를 넘음. 최종도 58.3%로 최고. 단 추론
LLM이라 로컬 배포 시 비용·인프라 부담.

**⑤ 임베딩으로 judge 근접: 리랭크 70.8% (I) — 현재 노선**
judge를 안 쓰고 **입력 정제(프랜차이즈·업종 필터) + HyDE 문서 개선(막연한 맛집 = 로컬
맛집 신호)** 으로 임베딩 리랭크를 62.5%→70.8%로. judge(75%)에 근접하되 **비용은 임베딩
수준.** (하이브리드 H는 키워드가 노이즈라 오히려 후퇴, 폐기)

## 리랭크 방법별 recall@K (K별로 따로)

두 갈래 실험을 K별로 모았다. **분모 11케이스/21정답**(리랭크 거친 케이스; 위 메인 표의
12/24와 %는 다르나 적중 개수는 같음). 값 = **정답단위% / 케이스단위%**. ★ = 그 K의 최고.

**동일 후보군 head-to-head** ([rerank_methods.md](rerank_methods.md)) — 본문/스니펫 HyDE는
같은 HyDE 문서 공유, 본문만 새로 크롤:

| **@10** | 정답 / 케이스 |    | **@15** | 정답 / 케이스 |
|---|---|---|---|---|
| 본문 HyDE | 66.7 / 90.9 |  | 본문 HyDE | 71.4 / 90.9 |
| 스니펫 HyDE | 71.4 / 81.8 |  | 스니펫 HyDE | ★85.7 / ★100.0 |
| 스니펫 judge | ★81.0 / 81.8 |  | 스니펫 judge | 85.7 / 81.8 |

| **@20** | 정답 / 케이스 |    | **@25** | 정답 / 케이스 |
|---|---|---|---|---|
| 본문 HyDE | 81.0 / ★100.0 |  | 본문 HyDE | ★90.5 / ★100.0 |
| 스니펫 HyDE | 85.7 / ★100.0 |  | 스니펫 HyDE | 85.7 / 100.0 |
| 스니펫 judge | ★90.5 / 90.9 |  | 스니펫 judge | ★90.5 / 90.9 |

**K별 승자 요약**
- **@10**: judge(81.0) — 최상위 정렬은 추론이 강함.
- **@15(운영점, keep=15)**: 스니펫 HyDE = judge 정답 동률(85.7), **케이스는 스니펫 HyDE 100 > judge 81.8**.
- **@20**: judge 정답 최고(90.5), 케이스는 본문·스니펫 HyDE가 100.
- **@25**: 본문 HyDE가 judge와 정답 동률(90.5)까지 따라오나, 그건 크롤 4.6배·토큰 9배의 대가.

**리랭크 단계 비용** (전체 파이프라인 아님) — 토큰은 **LLM(비쌈) vs 임베딩(쌈) 분리**:

| 방법 | LLM 토큰(실측) | 임베딩 토큰(근사) | 시간/케이스 | 인프라 |
|---|---|---|---|---|
| 본문 HyDE | 4,700 | ~495,566 | 7.61s | 임베딩 + **크롤** |
| 스니펫 HyDE | 4,700 | ~50,528 | 1.64s | 임베딩만 |
| 스니펫 judge | **34,579** | 0 | 1.45s | **추론 LLM** |

> LLM 토큰과 임베딩 토큰은 **단위·단가가 다르다**(합산 금지). 비싼 축(LLM)에서 **judge가
> HyDE의 ~7.4배**. HyDE의 임베딩 토큰이 큰 건 스니펫/본문을 통째 벡터화하기 때문(judge는
> 후보당 짧은 제목 2개만 읽음). 리랭크 없음/plain 임베딩 포함 4방법 K스윕은
> [rerank_ksweep.md](rerank_ksweep.md).

**결론**: 운영점 @15에서 **스니펫 HyDE가 judge와 대등(케이스는 우위)**, 추론 LLM 없이 임베딩
비용으로 달성 → 최종 노선 타당. **본문 HyDE는 이득 없이 비용만 커 폐기.** judge의 @10 우위는
추론 LLM 인프라를 요구하므로, 그 트레이드오프는 **로컬 LLM 기준으로 재검증**해야 확정된다
([local_llm_plan.md](local_llm_plan.md)).

## 남은 누수 (funnel)
```
수집 95.8% → 1차필터 83.3% → 리랭크 70.8% → 최종 50%
              └ 창원 횟집 되묻기(구조적 −3)      └ 최종 LLM이 리랭크 무시(−5)
```
- **되묻기 케이스 진행** 시 +3, **최종 LLM이 리랭크 순위 존중** 시 +5 여지.
