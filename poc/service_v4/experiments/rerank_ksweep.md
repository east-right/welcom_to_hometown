# 리랭크 방법별 recall@K (최종 LLM 선정 이전, 리랭크 순위 기준)

v4 기준. **최종 모델 선정이 아니라 리랭크가 만든 순위**에서 정답이 상위 K 안에 드는 비율.
과거 원자료(`experiments/{C,G,I}.json` + 그 `tool_file` 덤프)에서 재구성. 재현 스크립트
`experiments/_ksweep.py`.

- **분모: 11케이스 / 정답 21개** — 리랭크를 실제로 거친 케이스만(1케이스는 되묻기/재검색으로
  rerank 산출물이 없어 제외). ※ `metrics.md`는 12케이스/24정답 기준이라 %가 다르지만 **적중
  개수는 동일**(예: HyDE@15 = 17개 = metrics의 70.8%=17/24 = 여기 81.0%=17/21).
- 케이스별 리랭크 후보 수 = **28~59개** (전부 25 초과) → @25도 의미 있음.
- ①②③은 **같은 I 런 후보군 공통**(수집·필터 동일), 순위 매기는 방법만 다름.
  ④ judge는 별도 G 런(자기 수집).

## recall@K  (정답단위% / 케이스단위%)

| 방법 | @10 | @15 | @20 | @25 |
|---|---|---|---|---|
| **① 가장 기본** (수집순서, 리랭크 없음) | 57.1 / 81.8 | 66.7 / 81.8 | 76.2 / 90.9 | 76.2 / 90.9 |
| **② 쿼리-문서 임베딩** (HyDE 아님) | 66.7 / 72.7 | 76.2 / 81.8 | 81.0 / 90.9 | 85.7 / 90.9 |
| **③ HyDE 임베딩 + 필터** | 57.1 / 72.7 | 81.0 / 81.8 | 85.7 / 90.9 | 85.7 / 90.9 |
| **④ LLM-as-judge** | **85.7** / 81.8 | **85.7** / 81.8 | **90.5** / 90.9 | **90.5** / 90.9 |

(정답단위 = 정답 21개 중 K위 안에 든 수 / 케이스단위 = 케이스당 정답 하나라도 K위 안)

## 토큰·시간 (전체 파이프라인, 각 런 summary 기준)

| 방법(런) | tok_in | tok_out | 평균 소요 |
|---|---|---|---|
| ③ HyDE (I) | 230,066 | 10,944 | 38.7 s/케이스 |
| ④ judge (G) | 217,202 | 12,417 | 39.5 s/케이스 |
| ② HyDE 스니펫(참고, C) | 217,769 | 11,421 | 38.5 s/케이스 |

※ 위 토큰·시간은 **수집·크롤·요약·최종선정까지 포함한 전체 흐름**이라 리랭크 단독 비용이
아니다. 리랭크 단계의 한계비용만 보면: ①은 0(리랭크 콜 없음), ②③은 임베딩 콜(+③은 HyDE
문서 생성 1콜), ④는 추론 LLM 콜(그래서 out 토큰이 가장 큼: 12.4k).

## 읽는 법 (요약)

1. **리랭크는 실제로 효과가 있다** — 같은 후보군인데 ①(수집순서) 대비 ②③이 모든 K에서 상승.
   특히 @25에서도 ①76.2 → ③85.7 → 즉 수집순서로는 25위 밖에 묻힌 정답을 리랭크가 끌어올린다.
2. **HyDE는 중간 K(@15)에서 임베딩을 앞선다** — ②76.2 vs ③81.0 @15. 다만 @10에선 ③이 낮음
   (57.1) → HyDE는 상위권 미세정렬보다 15위권 안에 모으는 데 강함(현 파이프라인 keep=15와 정합).
3. **judge가 전 구간 최고, 특히 상위권** — @10에서 85.7로 압도적. 추론이 flat-cosine 한계를
   뚫어 정답을 top-10에 몰아넣음. 대신 out 토큰·비용이 가장 큼(추론 LLM).

> 비용 대비: **judge = 최고 정확·최고 비용**, **HyDE = judge 근접(중간 K)·임베딩 수준 비용**,
> **plain 임베딩 = 무난**, **리랭크 없음 = 상위권에서 확연히 열세.**
