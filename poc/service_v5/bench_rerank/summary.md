정답셋은 `test.json`(= `test_LLM_da.json`) 기준 **정답 24개 / 11질문**으로 통일했다.

## 표 1. 오픈 LLM vs 우리 시스템 — 정답단위 최종 recall
`test_LLM_da.json`(정답 24개, 오픈 API 추천 포함) 기준.

| 소스 | 최종 recall | 격차(우리 대비) |
|---|---|---|
| **우리 시스템 (Gemini 파이프라인)** | **17/24 = 70.8%** | — |
| chatgpt | 14/24 = 58.3% | −12.5%p |
| gemini (단독) | 11/24 = 45.8% | −25.0%p |
| perplexity | 10/24 = 41.7% | −29.1%p |

우리 파이프라인이 모든 오픈 LLM 단독보다 두 자릿수 우위.

## 표 2. HyDE 리랭크 방법 비교 — 정답단위 리랭크 Recall@15
전 11질문, 정답 23개(신림정 반영·가포옛날영도집 미반영 시점 측정), 임베딩 방식 통일·앵커만 변경.

| 리랭크 방식 | 신호 | 추가 비용 | Recall@15 |
|---|---|---|---|
| No-rerank (수집순) | 카카오 정확도순 | 0 | 47.8% |
| 스니펫 히트 수 | 블로그 노출량 | 0 | 47.8% |
| 키워드 겹침 (lexical) | 쿼리 단어 매칭 | 0 | 65.2% |
| Raw query cos | 원쿼리 임베딩 | 임베딩 | 73.9% |
| HyDE single | 가상문서 1개 | +LLM 1콜 | 78.3% |
| **HyDE multi (채택)** | 3-facet | +LLM 1콜 | **87.0%** |

multi-HyDE가 최고. 리랭크 없음 대비 +39.2%p, raw cos 대비 +13.1%p, single 대비 +8.7%p.

## 표 3. 백엔드별 비교 — Gemini vs 로컬 2모델
조합 1 = 에이전트만 로컬, 나머지 Gemini. 전체 11질문, 정답 24개.

| 구성 | 정답 recall | 케이스 recall | 평균 시간 | 툴 루프 |
|---|---|---|---|---|
| Gemini 전량 | 17/24 = 70.8% | 11/11 = 100% | 28.1초 | 0 |
| gemma-4-31B (에이전트만 로컬) | 15/24 = 62.5% | 10/11 = 90.9% | 39.5초 | 0 |
| qwen3.8-27B (에이전트만 로컬) | 10/24 = 41.7%\* | 8/11 = 72.7% | 57.5초\*\* | 2/11 폭발 |

\* qwen은 툴 루프로 2케이스(정답 6개)를 통째로 실패한 것 포함.
\*\* 성공 케이스 평균(실패는 30콜 상한까지 돌아 더 김).

**gemma 조합 변형 (가포 단일):**

| 조합 | 로컬 범위 | 가포 시간 | 가포 recall |
|---|---|---|---|
| 조합 1 | 에이전트만 | 46.0초 | 4/4 |
| 조합 2 | 에이전트 + 최종점수(SELECT) | 55.6초 | 3/4 |
| B (전부 로컬) | 에이전트+요약+HyDE+SELECT | ~112초 | (서버 끊김) |

해석: gemma는 케이스 recall 90.9%로 Gemini에 근접하고 툴 루프도 0으로 안정적이다.
정답단위 62.5%로의 하락은 주로 앞단(검색어·region 생성)에서 나온다 — 예: '신림역 감성카페'처럼
수식어를 못 떼어 로드트립을 수집에서 놓침. 최종 선택(SELECT_SCORE=Gemini) 품질은 유지되며,
로컬 손실은 프롬프트 보강으로 회복 가능한 성질이다. qwen은 툴 루프가 확률적으로 폭발하고
느려 부적합.

## 표 4. gemma-4-31B — speculative decoding 설정별 속도
가포 단일, 조합 1.

| spec 방식 | 가포 시간 | vs 디폴트 | recall |
|---|---|---|---|
| MTP | 46.0초 | −31% | 4/4 |
| n-gram | 58.6초 | −12% | 4/4 |
| 디폴트 (spec 없음) | 66.9초 | 기준 | 4/4 |

속도 MTP > n-gram > 디폴트. recall은 3설정 동일(spec은 출력 불변, 속도만 개선).

## 결론
- **리랭크**: multi-HyDE가 방법 중 최고(87%), 우리 시스템은 오픈 LLM 전부를 앞섬(70.8%).
- **백엔드**: gemma가 로컬 실용 후보(케이스 90.9%·40초·툴루프 0), qwen은 부적합.
- **로컬 최적 구성**: 에이전트만 로컬(조합1) + gemma + MTP spec.
